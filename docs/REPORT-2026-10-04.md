## 2. เรื่องที่ตัดสินใจเองพร้อมเหตุผล

รายการเต็มอยู่ใน [DECISIONS.md](DECISIONS.md) ส่วน "Decisions made while building" สรุปข้อสำคัญ:

**ข้อ 7 ของแผน**
- **ล็อกชั่วคราว:** ผิด 3 ครั้ง → 30 วิ, ล็อกครั้งถัดไปเพิ่มเป็นสองเท่า (1, 2, 4, 8 นาที) เพดาน 10 นาที, ใส่ถูกแล้วรีเซ็ต; ตัวนับเก็บใน flash (`security.ini`) ถ้า DS3231 มีเวลาจะนับต่อจากเวลาจริง ถ้าไม่มีจะนับใหม่ทั้งรอบ (ปลอดภัยไว้ก่อน)
- **Lock message:** สูงสุด 20 ตัว (บรรทัดเดียว) ใช้ตัวพิมพ์เล็ก/ใหญ่/เว้นวรรคได้
- **toast / หน้าผลลัพธ์:** toast 1.2 วิ; ตัวเลขในผังใช้ตามผัง (Sent 1 วิ, Saved 1.2, Connected 1.5, Wrong PIN 1.5)
- **timeout:** IR learn 15 วิ, WiFi connect 15 วิ
- **combo เข้าเมนูฉุกเฉิน:** Power ค้าง หรือ Cancel ค้าง + OK (บนหน้า Boot status เท่านั้น)
- **โซนเวลา:** UTC+7 คงที่ DS3231 เก็บเวลาท้องถิ่น
- **หน้า Firmware:** codename "PIE" ยังไม่ใส่มุก
- **สีเน้น:** ยังไม่ใช้ ทุกสีอยู่ที่ `firmware/ui/colors.h` (`kAccent` เปลี่ยนที่เดียว)

**รหัสฉุกเฉิน = `40917263`** (กระจายเป็นค่าคงที่ของ hash ใน `firmware/app/security.cpp` ประกอบในฟังก์ชันตรวจเดียว) - **เปลี่ยนเลขได้ที่ค่าคงที่ 4 ตัวบนสุดของไฟล์นั้น** (ค่าเหล่านี้เป็นส่วนผสมของ hash PIN ด้วย เปลี่ยนแล้ว PIN ที่ตั้งไว้เดิมต้องตั้งใหม่)

**ข้อ [ร่าง] อื่น**
- ไอคอนเทา = tint ตอนวาด (ตามแผน) · Bottom bar ตาม mockup · ท้ายแถว ✓/กุญแจ/แท่งสัญญาณ/จุด ตาม mockup
- Settings: แก้ค่าแล้วบันทึกทันทีเมื่อกด OK, ความสว่างเปลี่ยนสดระหว่างแก้, ค่าตัวเลขเป็นขั้น (ความสว่าง 10-100 ทีละ 10, Dim after 10/20/30/60/120/300 วิ/Never, Sleep after 1-30 นาที, Low battery 5-30%)
- Sleep mode: Deep = deep sleep (OK/Power ปลุก กลับมาโมดูลเดิมผ่าน lock), Light = light sleep, Off = ปิดจออย่างเดียว, Never = ไม่ sleep เองเลย; ปุ่ม Power สั่ง sleep ตามโหมดเสมอ (Never → ปิดจอ)
- BT: advertise เมื่อเข้าเมนู หยุดเมื่อออกถ้ายังไม่ต่อ (ตามร่าง), ชื่ออุปกรณ์ "Pie Controller", หน้า Keys ของ Remote (ผังบอกว่ามีแต่ไม่มี node) ใช้รหัส `B1k`
- WiFi Disconnect ตัดทันที มี toast ไม่มี dialog (ตามร่าง)
- NFC: Classic อ่านทุก block ด้วย key มาตรฐาน (อ่านไม่ได้เก็บเป็น `??`), บัตรอื่นเก็บแค่ UID (ตามร่าง); emulate ได้เฉพาะ dump UID-only หรือ Classic ที่ครบ ไม่งั้นขึ้นข้อความ "needs full MIFARE authentication"
- IR เก็บไฟล์ละหมวดบน SD (`sd:/ir/<หมวด>.ir`) - rename/ลบหมวด = ไฟล์เดียว
- รายการเลื่อนวน (< ที่บนสุดไปล่างสุด) เพราะมีแค่ 2 ปุ่มเลื่อน
- fade ระหว่างหน้า = มืดลงแล้วสว่างขึ้น (ตามโน้ต M2), fade เข้า dialog = cross-fade ให้หน้าหลังยังเห็น
- ตาราง pin: ใช้ร่างในแผน + PN532 IRQ 41 / RST 42; กฎ pin ห้าม 26-37 ทั้งหมด (N16R8 ใช้ 26-32 กับ flash และ 33-37 กับ PSRAM ไม่ใช่แค่ 35-37)

**emulator**
- หน้าต่างเป็นหน้าเว็บที่ exe เสิร์ฟเอง เปิดด้วย Chrome/Edge โหมด app → exe ไฟล์เดียว ไม่ต้องมี GUI toolkit และ `shot-ui` ใช้หน้าเดียวกันได้
- ความปลอดภัย: ผูก 127.0.0.1 เท่านั้น + token สุ่มในไฟล์ `.sim-session.json` + ตรวจ Host/Origin (กัน DNS rebinding) - ทดสอบแล้วว่าไม่มี token / Origin แปลก / Host แปลก ได้ 403
- `sim press` จาก terminal รอเพิ่ม 300 ms หลังปล่อย (ขึ้นใน log เป็น `wait 300`) ให้ `sim shot` ถัดไปเห็นผลจริงไม่ใช่กลาง animation
- ปุ่มที่แตะเร็วกว่า 1 tick ถูกค้างไว้ 50 ms (ไม่งั้นเฟิร์มแวร์มองไม่เห็นการกด)
- ไลบรารี ESP32: Adafruit ST7735 (ส่งเฉพาะหน้าต่างที่เปลี่ยน), LittleFS/SD ของ core, RTClib, Adafruit PN532, IR ใช้ RMT ของ ESP-IDF โดยตรง (ตามแผน) พร้อมตัวเข้า/ถอดรหัส NEC/Samsung/Sony/RC5, NimBLE-Arduino (HID, bond แบบทิ้งเก่าสุด, ยืนยันรหัสจับคู่จาก dialog), platform espressif32 6.9.0 (Arduino core 2.0.17)

## 3. จุดที่ทำไม่ได้ / ลดรูป / ต่างจากผังหรือภาพ

- **ESP32-S3 compile ได้แต่ยังไม่เคยรันบนบอร์ดจริง** (ยังไม่มีของ) - ทุก driver ระบุใน STATUS.md
- **NFC emulate บน PN532:** ชิปส่ง ID 3 ไบต์ของตัวเอง ไม่ใช่ UID ของ dump; เขียน UID (block 0) บนบัตร magic ไลบรารีไม่รองรับ - ใน emulator ทำได้ครบ บนเครื่องจริงจำกัด
- **BLE บนเครื่องจริงไม่รู้ชื่อ host** (bond เก็บแค่ address) จึงแสดงเป็น address; ใน emulator แสดงชื่อ
- **ตื่นจาก deep sleep กลับมาแค่ระดับโมดูล** (เช่นเมนู IR) ไม่ใช่หน้าลึกในโมดูล
- **`onExit` จำกัดเวลา 200 ms แบบวัดผล** ตัดกลางคันไม่ได้เพราะเฟิร์มแวร์ทำงาน thread เดียว
- **pack เกมบน SD:** มีตัวตรวจ `validatePack()` ครบ แต่ engine จริงยังไม่มี - `sprite2d` แสดงภาพ scene ของ pack, `menu_flow` แสดงหน้า list/message มาตรฐาน; เกมในตัวทำ Snake/Pong/Reaction (ระดับละเกม) แทน SNAKE/PONG/FISCH ใน mockup
- **โลโก้บูต** ไม่มีใน export ของ Studio จึงตัดจากภาพ mockup "Boot Load" ด้วย `tools/png_to_pic.js`
- **Home wallpaper** ใน mockup เป็นภาพร่าง placeholder - เฟิร์มแวร์ใช้ wallpaper จาก theme ถ้ามี ไม่งั้นพื้นเทาอ่อน
- **นาฬิกาใหญ่** ใช้ฟอนต์ 8×8 ×3 + โคลอนแคบ เลยต่างจาก mockup เล็กน้อยที่ระยะโคลอน
- **ลำดับหมวด/dump** เรียงตามตัวอักษร (mockup เรียงตามที่สร้าง)
- **เทียบภาพ:** 96 หน้า → ตรง pixel 31 หน้า, ต่าง <2% (ข้อความ/ข้อมูลตัวอย่างเช่นชื่อ เวลา เลขเวอร์ชัน) 47 หน้า, ที่เหลือ 18 หน้าต่างเพราะ state ของภาพไม่เหมือนกัน (เช่น mockup เลือกคนละแถว, PIN กรอกไปกี่หลัก, เกมใน mockup เป็นภาพ placeholder) - ดูภาพคู่ทุกหน้าได้ที่ `docs/report/gallery-*.png`
- **macOS** ตัดออกจาก CI ตามที่แผนอนุญาต
- เปลี่ยน project folder จากปุ่มในหน้าต่างไม่ได้ (ปุ่มบอกวิธีเปิด `sim gui --project …` แทน) เพราะ session ผูกกับโฟลเดอร์ตั้งแต่เริ่ม

## 4. วิธีทดสอบที่ใช้ และสิ่งที่ยังไม่ได้ทดสอบ

**ทดสอบแล้ว**
- `ctest` 23 รายการ เขียวทั้ง Linux และ Windows (MSVC ใน CI): unit test, script 18 ตัว (flow-walk 8 + feature 10), build-fail test 2 + control, เส้นทาง terminal (`sim open` → กดไป Settings → `sim state` ได้ `Home/Menu/Settings` → `sim shot` ได้ PNG สี)
- hash ภาพเหมือนกันทุกเครื่อง: Windows exe (MinGW + Wine ในเครื่องนี้) ผ่าน script ทั้งหมดด้วย hash เดียวกับ Linux
- เทียบ pixel ทุกหน้ากับ `screens/*.png` ด้วยตา + เครื่องมือ diff (แก้จนตำแหน่ง/ขนาดตรง)
- หน้าต่าง: ขับด้วย Playwright แบบเวลาจริง - กดคีย์, combo ค้าง Z แล้ว →, คลิกขวาล็อกปุ่ม, พิมพ์ในช่องแล้วปุ่มไม่ไปถึงเครื่อง, command log, ปิดหน้าต่างแล้ว session ของ `sim gui` ปิดตามใน ~4 วิ
- `shot-ui` ใน cloud container ทำงานได้ด้วย Chromium ของ Playwright (`/opt/pw-browsers`)
- import theme format 2 (`.c16`) แล้วแสดงสีถูก: **ทดสอบกับไฟล์ที่ผมสร้างเองตามสเปก `THEME_FORMAT_SPEC` ของ Studio** (`sim/fixtures/sunset-theme.zip`) **ยังไม่ได้ทดสอบกับ theme pack ที่ export จาก Studio จริง** เพราะ zip ไม่มีตัวอย่าง
- ESP32-S3: compile ใน CI ผ่าน - **หมายเหตุ:** ช่วงแรก job นี้ขึ้นเขียวทั้งที่ build ล้มจริง เพราะ `| tee` กลืน exit code; เจอเองหลังเพิ่ม `pipefail` แล้วแก้ 2 รอบ (เลขเวอร์ชันไลบรารี PN532 ที่ไม่มีจริง, ชื่อชนกับ macro `bit()`/`F()` ของ Arduino) ตอนนี้ CI รายงาน error ของ compiler เป็น annotation และไม่ปล่อยผ่านแล้ว (ในเครื่องนี้ network policy บล็อก `dl.registry.platformio.org` / `api.registry.platformio.org` และไฟล์ release บน GitHub จึง build เองไม่ได้)

**ยังไม่ได้ทดสอบ**
- ทุก driver บนฮาร์ดแวร์จริง (จอ, ปุ่ม, SD, RTC, IR, NFC, WiFi, BLE, sleep, กระแสไฟ)
- `sim gui` เปิดหน้าต่างจริงบน Windows (ทดสอบได้แค่ headless + Wine) - ฝากลองข้อ 5
- ความเร็ว transition fade เต็มจอบน SPI จริง (คำนวณได้ ~12 ms/เฟรมที่ 27 MHz น่าจะไหว ยังไม่ได้วัด)

## 5. สิ่งที่ต้องให้ผู้ใช้ทำต่อ

1. **ตรวจตาราง pin** ใน `firmware/board/board_profile.h` กับบอร์ดจริงเมื่อของมา แล้วทำตาม `docs/BRINGUP.md` ทีละขั้น (บอกว่าต่ออะไร แฟลชอะไร ควรเห็นอะไร)
2. ลอง `sim gui` บน Windows: ดาวน์โหลด `sim.exe` จาก CI (artifact `diy-flipper-sim-windows`) วางในโฟลเดอร์ repo แล้วรัน `sim.exe gui` ในโฟลเดอร์ repo
3. ดู branch แล้วสั่ง merge (บอกได้ถ้าอยากให้เปิด PR)
4. ถ้าอยากให้ build ESP32 ใน cloud session ได้เอง: เพิ่ม `dl.registry.platformio.org`, `api.registry.platformio.org` และ `github.com` ใน Allowed domains ของ environment (Network access) - ตอนนี้ CI build แทนได้อยู่แล้ว
5. export เพิ่มจาก Studio ถ้าต้องการ: โลโก้บูตเป็น asset, ฟอนต์ตัวเลขใหญ่ของนาฬิกา, theme pack format 2 ตัวจริงสักชุดไว้ทดสอบ
